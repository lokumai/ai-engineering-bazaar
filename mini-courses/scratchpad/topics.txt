33) advanced_agent_servers ("Advanced Agent Servers"; drafted in 3_expert/advanced_agent_servers.md from these notes, to be revised when the module is planned):
  1. Aegra (native Redis worker queue + lease locks; simple blocking pipelines; lease-based heartbeat in Redis for crash recovery; Redis pub/sub for streaming to the frontend; needs custom application-level heartbeat loops; brittle: if a worker crashes without a standalone sweeper script, jobs disappear. Choose it for a lightweight, simple, multi-language cluster where tasks are linear and memory costs must stay minimal: absolute minimum infrastructure overhead, zero RAM accumulation (data leaves memory on pop), supported in every programming language.)
  2. SkeinJS (BullMQ on Redis; complex interlocking primitives: sorted sets (ZSETs) schedule jobs by timestamp, hashes store job states, lists queue active tasks; BullMQ's stalled-job check for crash recovery; Redis pub/sub for streaming to the frontend; heavily coupled to its runtime (Node.js for BullMQ); erases transaction footprints on job success; large cluster key bloat. Choose it for a Node.js/TypeScript backend that needs rich agent automation loops now without rewriting queue logistics: fast development, built-in exponential backoff retries, cron jobs and rate limits, native admin dashboards.)
  3. Vercel AI SDK with serverless durable orchestration (Inngest/Temporal): a stateless, transient architecture that treats an agent run not as an open loop but as a chain of small, discrete HTTP events that can be paused, frozen to a database and thawed on another machine; virtual actors / state machines; deep lock-in to proprietary cloud APIs or complex self-hosted runtimes; cold-start delays when a function wakes; breaks persistent live TCP/WebSocket lines. Choose it on a purely serverless platform (like Vercel) for slow, hours-long parallel analysis: no servers to provision or pay for idle, agents run for hours or days without fearing server crashes, handles complex multi-step tool dependencies naturally.
  4. Redis Streams (the "Kafka-lite" log: time-indexed append-only logs; unacknowledged messages tracked by the built-in PEL (pending entries list); heavy, tedious low-level loop boilerplate; no native execution delay buffers; serious OOM risk if stream limits (MAXLEN) are forgotten. Choose it for an enterprise-grade event-driven multi-agent mesh, real-time logging pipelines or custom distributed system graphs: database-level fault tolerance through the PEL, an immutable audit trail of every step an agent took, native multi-consumer fan-out.)
