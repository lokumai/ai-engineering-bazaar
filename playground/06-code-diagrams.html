Code blocks and diagrams — three colour systems

Today both are one grey on another grey, so a keyword looks like a comment and a highlighted diagram node looks like an ordinary one. Each option below gives code six token roles and diagrams three node roles, which is enough to carry meaning and few enough to learn.

The diagram node roles matter for your corpus specifically: your mermaid rails already mean three things — done, you are here, and not yet — and right now all three look the same.

1

Light, ink-first

code on paper, like the rest of the page

Why: nothing on the page goes dark, so a module reads as one surface and a code block does not punch a hole in it. Cost: the lowest contrast of the three, and light syntax colours are harder to keep accessible at small sizes.
2

Dark slab

what engineers see in their editor all day

Why: the highest contrast, instantly familiar, and code stops competing with prose because it is obviously a different kind of thing. Cost: a dark slab in a light page is a strong visual break, and a module with five code blocks starts to look striped.
3

Banner palette

cobalt, teal, clay and ochre from your tile artwork

Code

Diagram

Done→ Done→ You are here→ Next→ Later
cobalt teal clay ochre stone
Why: the only one that makes a code block look like it belongs to this project rather than to a generic theme, and it reuses colours the reader already met in the banner. Cost: four hues is a tight budget for syntax, so complex code has fewer distinctions than options 1 and 2 give it.

My read: 2 for code, because the audience reads dark code all day and the contrast is honest, and 1 or 3 for diagrams, because a diagram sits in the argument of the prose and should not break the page. Mixing them is normal: dark code blocks with light diagrams is what most documentation sites actually ship.

One technical note. Whichever you pick, diagram colour has to be applied by class rather than by hex in the markdown. Your corpus writes style A fill:#90EE90 today and the build rewrites nine known hexes into themed classes; any other hex fails the build. Three named roles — done, here, not yet — would replace that mechanism with something an author can use without memorising hexes.
