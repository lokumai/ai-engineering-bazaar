How should the Catalog menu let a reader open any level of either track?

Each option below is the real bar with the menu open. Every row is clickable, and the line under each picture says where it would go. The phone version sits beside it.

  • D1 Two columns
  • D2 Tabs in the menu
  • D3 Two links per level
D1

Two columns, one per track

Recommended

The menu widens to two columns. Each column is headed by its track, which opens that track's whole catalog, and lists the five levels under it.

  • Every destination is visible and one click away. Nothing is hidden behind a tab.
  • Every row is a plain link, so it keeps working with no JavaScript, like today's menu.
  • Twice as wide on a desktop (about 450px). On a phone the columns stack, so the menu gets taller instead.

Why recommended: the two tracks have the same levels, and side by side is the plainest way to say that, with no state to learn.

Seen on

GitHub's Solutions menu (a column each for company size, use case and industry), Khan Academy's Courses menu (a column per subject), and Stripe's Products menu.

D2

Tabs at the top of the menu

The menu keeps its size and today's list. Two tabs above the list, For Engineers and For Everyone, switch which track the levels open into. The tab of the track the reader is in is selected when the menu opens.

  • The menu stays the size it is now, on every screen.
  • The other track's levels are one extra click away, and a reader has to notice the tabs to find them.
  • The tabs need JavaScript (or a radio-button trick). Without it, only one track's levels can be shown.

Seen on

GitHub's branch picker (Branches and Tags tabs over one list), and the Swift and Objective-C switch at the top of Apple's developer documentation.

D3

One level list, two links per level

Today's list, with two small links at the end of each row: Engineers and Everyone. The level name and its count stay where they are. The link for the page the reader is on is filled.

  • Compact: one list, both tracks one click away.
  • The targets are small (26px tall on a desktop, 32px on a phone), and the row itself is not a link, which readers may try first.
  • Rare in navigation menus, so it is the least familiar of the three.

Seen on

Not common in menus. The nearest familiar version is a table with several small links per row, like the Node.js previous releases page (Releases, Changelog, Docs on each version).
