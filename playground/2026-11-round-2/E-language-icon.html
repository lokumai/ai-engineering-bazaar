What should the language button in the bar show, instead of the globe?

Each option is the real bar on LLM Fundamentals with the language menu open. Pick a language in the menu and the button and the page follow it. Beside it, the button on its own for each language, and with the keyboard focus ring.

  • E1 文A glyph
  • E2 Aa glyph
  • E3 Language code
  • E4 Flag and code
  • E5 Flag alone
E1

The translate glyph

Recommended

A Latin A beside a character from another script, the mark Google Translate made familiar, drawn in the bar's 1.5px line so it matches the theme and repository icons.

  • It means "language" and nothing else. A globe can also mean region, website or the internet.
  • Stays a 33px square, so the bar keeps its row of equal buttons.
  • Does not say which language the page is in. The check in the menu does, and the page itself does.

Why recommended: it is the most widely recognised language mark after the globe, it means the same thing to an English, Turkish or Persian reader, and it carries no country.

Seen on

Wikipedia (the language button at the top of every article), Google Translate, Chrome's translate button, and Material's own "translate" icon.

E2

An Aa glyph

The letters Aa, set in the bar's own type, standing for "text" and the language it is in.

  • Quiet and typographic. No drawing to get right at 16px.
  • Most readers know Aa as text size or reading settings (Safari's reader, Apple Books, Kindle), so many will expect a font menu here.
  • Latin letters only, so it says nothing to a reader of the Persian page that the 文A glyph does not say better.

Seen on

Rare as a language button. Common as a text-settings button: Safari's reader view, Apple Books, the Kindle app.

E3

The language code

The button shows the code of the language being read: EN, TR or FA. The menu repeats the codes beside the names.

  • The only option that answers "which language am I reading" from the bar.
  • It is what the shell mockup drew: 01 has a TR square in exactly this slot.
  • Two letters can read as a label rather than a button, and FA is less obvious to a Persian reader than فا. The chrome is English, so FA stays consistent with it.

Seen on

europa.eu and many government and airline sites, usually with a small chevron or globe beside the code.

The button on its own

E4

A small flag beside the code

The button widens like the repository button and shows the flag of the current language, then its code. The menu puts a flag beside each name. Persian can take Iran's flag, or no flag: the button then shows the code alone, and the menu a small chip with the script itself, فا.

  • UX guidance generally advises against flags for languages: a flag stands for a country, and a language is not one. English is not only British (the US flag is the usual alternative, and either one leaves the other readers out).
  • Persian is spoken in Iran, Afghanistan and Tajikistan, and Iran's flag is politically loaded: the current flag and the older Lion and Sun flag each read as a statement. The no-flag chip avoids that, but then one language looks different from the other two.
  • Flags are quick to scan, but the UK flag's navy nearly disappears on the cobalt bar without its hairline.

Seen on

The default switcher of WordPress translation plugins (WPML, Polylang). Apple uses flags only on its country and region page, which is the case flags are right for.

E5

The flag alone

The flag of the current language replaces the glyph inside the 33px square. For Persian, Iran's flag, or no flag: the button then shows فا.

  • The most compact way to show the current language, and the square stays square.
  • Everything said against flags under E4 applies, and more strongly: with no code beside it, the flag is the whole message.
  • A flag in a button reads as "country" or "region" to many readers, so some will expect a shipping or locale setting.

Seen on

Booking.com's header (a flag that opens the language and region list) and many hotel and shop sites.
