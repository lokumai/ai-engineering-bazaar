On T4. The overlap bug, measured. I reproduced it in Chrome at 1440px on /courses/fundamentals/observability/. The content column runs from x=376 to x=1032 and the right rail starts at x=1056, but mermaid injects an SVG 1,423px wide starting at x=144, so it paints across both rails and past the window edge. It is not a CSS width problem: mermaid renders in the browser after the page loads, so the SVG arrives at its natural content width and escapes the scroll container that was meant to hold it. Between 90 and 145 elements per page sit outside the column. The rails I rebuilt for the new curriculum are wider still, so this got worse, not better. Every layout in 04 demonstrates the containment that fixes it.

What I need from you

  1. One vocabulary set A, B or C, or a mix such as “C but Mark as read”.
  2. One theme T1, T2, T3 or T4. You can also say “T1 structure with T4 colour”, which is a real option.
  3. One option per component navbar, catalog, layout, sidebar, progress, code, diagrams, dashboard, home.
  4. Anything missing tell me which screen you want to see before I start building.

Once you have chosen, the build order I would suggest is: naming and tokens, then the shell (navbar and sidebar), then the module page including the diagram fix, then the catalog, then home, then progress and account. Each of those is a step that can ship on its own.
